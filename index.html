一、背景I. Background

FeedMob Pixel 是什么

FeedMob Pixel 是公司内部开发团队构建的 Web 端归因工具。广告主将一段代码嵌入自己的网页，FeedMob 即可识别来自自身渠道的流量，并在用户发生行为时完成转化归因——相当于在 Web 端充当自己的 Attribution Partner。

该工具最早服务于 Display Ads 时代，主要客户为 Chime。当时归因逻辑相对简单，背后积累的海量数据也从未被深度挖掘。

What is FeedMob Pixel

FeedMob Pixel is a web-based attribution tool built by our internal engineering team. Advertisers embed a code snippet on their web pages, enabling FeedMob to identify traffic from its own channels and attribute conversions when user actions occur — effectively making FeedMob its own Attribution Partner on the web side.

The tool was originally built during the Display Ads era, primarily serving Chime. Attribution logic was straightforward at the time, and the substantial data it accumulated was never deeply analyzed.

二、为什么现在要做II. Why Now

CTV 带来的新机遇

随着 FeedMob 进入 CTV 领域（合作伙伴包括 Samsung CTV、LG、Pragmatic 等），Pixel 的战略价值发生了根本性转变。

CTV 跨设备归因困境

用户在电视上看到广告，但转化发生在手机或电脑上。广告曝光与转化设备完全分离，传统归因几乎失效。App 端有 MMP（如 AppsFlyer），但 Web 端对 CTV 的归因几乎是空白。

被忽视的价值：竞争情报

Pixel 不只采集 FeedMob 渠道的转化，还有广告主网页上所有用户的行为（all-ping 数据）。这意味着我们能看到竞争对手 CTV 渠道的转化效果——极具价值的市场情报，此前从未被挖掘。

The CTV Opportunity

As FeedMob enters the CTV space — with partners including Samsung CTV, LG, and Pragmatic — the strategic value of Pixel has fundamentally shifted.

CTV Cross-Device Attribution Gap

Users see ads on TV but convert on mobile or desktop. Exposure and conversion devices are completely separated, making traditional attribution nearly useless. Apps have MMPs (e.g. AppsFlyer), but web-side CTV attribution is essentially a blank slate.

Overlooked Value: Competitive Intelligence

Pixel captures not only FeedMob-attributed conversions, but all user behavior on advertiser pages (all-ping data). This means we can analyze competing CTV channels' performance — highly valuable market intelligence that has never been extracted.

三、现状与问题III. Current State

数据沉睡在数据库里

Pixel 每天采集的数据，目前全部存储在 PostgreSQL 数据库中，处于完全沉睡的状态：

  • 没有可视化界面
  • 没有实时查询能力
  • 没有归因分析逻辑
  • 没有对竞争对手数据的挖掘

数据有巨大的商业价值，却还没有得到有效使用。

Data Locked in the Database

Pixel collects data daily, all of which currently sits in a PostgreSQL database, completely dormant:

  • No visualization layer
  • No real-time query capability
  • No attribution analysis logic
  • No competitive data extraction

The data holds enormous business value — and none of it is currently being used.

四、我们要做什么IV. What We're Building

AI 原生分析平台

目标：构建一个 AI 原生的 Pixel 数据分析平台——不只是让人"可以查数据"，而是一个持续运转的 AI 分析师，主动发现异常和机会，推动行动，并持续优化自身的归因模型。

平台具备三个层次的能力：

1
响应式分析（基础层）

业务团队可以用自然语言实时查询 Pixel 数据，AI 动态生成分析视图，替代传统固定 Dashboard。

2
主动发现（核心层）

AI 不等人来问，24 小时持续监测数据，主动推送异常警报和商业机会：某 partner 转化率异常下降、某广告主 CTV 流量激增但预算未跟上（upsell 信号）、竞品渠道出现新的高转化模式等。

3
行动驱动（价值层）

AI 不止于"告诉你发生了什么"，而是直接生成可执行的行动建议和素材：为 AM 自动准备 CTV 归因 vs. 竞品对比的客户汇报；为 BD 识别竞品表现不佳的广告主，生成 outreach 话术；为 Product 推荐归因模型参数调整方案。

定位：独立系统，与现有 Femini 平台并行。Pixel 场景下 FeedMob 作为 attribution party，与 Femini 中作为 agency 的定位本质不同，现阶段不适合作为附加功能嵌入。

传统 BI 的逻辑是"人提问 → 工具回答"，AI 原生的逻辑是"AI 主动发现 → 推动人行动"。

An AI-Native Analytics Platform

Goal: Build an AI-native Pixel analytics platform — not merely a query interface, but a continuously operating AI analyst that proactively surfaces anomalies and opportunities, drives action, and continuously improves its own attribution model.

The platform operates across three capability layers:

1
Reactive Analytics — Foundation

Business teams query Pixel data in natural language. AI dynamically generates analysis views, replacing static dashboards.

2
Proactive Discovery — Core

AI doesn't wait to be asked. It monitors data 24/7 and proactively pushes anomaly alerts and business opportunities — e.g. a partner's conversion rate drops sharply, an advertiser's CTV traffic spikes but budget hasn't followed (upsell signal), or a competing channel shows a new high-conversion pattern.

3
Action-Oriented Output — Value

AI goes beyond reporting what happened — it generates actionable outputs: auto-prepared client reports for AMs with CTV attribution vs. competitive benchmarks; outreach copy for BD targeting advertisers where competing channels underperform; attribution model tuning recommendations for Product.

Positioning: Standalone system, parallel to Femini. FeedMob's role as an attribution party in the Pixel context is fundamentally different from its agency role in Femini — embedding it as an add-on is not appropriate at this stage.

Traditional BI: "Human asks → Tool answers." AI-Native: "AI discovers → Human acts."
五、技术架构V. Technical Architecture

三层架构思路

层级说明
数据层基于现有 PostgreSQL，传统工具开发，快速建立可复用的结构化查询框架。AI 帮助建立早期结构，而非每次重新分析原始数据。
MCP 智能层通过 MCP（非静态 API）连接数据层与分析层。MCP 能自主处理复杂组合调用、异常恢复、动态参数变化——API 是死的，MCP 是活的，是走向 AI 自主化的必经基础设施。
AI 原生前端不构建固定 Dashboard，由 AI 按需动态生成分析视图。自然语言提问 → MCP 取数 → 即时可视化。

Three-Layer Architecture

LayerDescription
Data LayerBuilt on existing PostgreSQL. Conventional tools, rapidly establishing reusable structured query frameworks. AI accelerates initial structure-building, not raw-data parsing on every query.
MCP LayerConnects data to analytics via MCP (not static APIs). MCP autonomously handles complex multi-step calls, anomaly recovery, and dynamic parameters. APIs are static; MCP is adaptive — essential infrastructure for AI autonomy.
AI-Native FrontendNo fixed dashboard. AI dynamically generates analysis views on demand. Natural language query → MCP data fetch → instant visualization.
六、实施路径VI. Implementation Phases

分阶段推进

Phased Rollout

1
数据摸底
Data Discovery

理解 Pixel 数据结构，建立数据字典

Map Pixel data schema, build data dictionary

梳理 PostgreSQL 中现有 Pixel 数据的字段、事件类型和数据量规模；确认数据完整性；与工程团队对齐数据写入逻辑；建立可复用查询框架。

Map existing Pixel data fields, event types, and volume in PostgreSQL. Confirm data integrity. Align with engineering on ingestion logic. Build reusable query frameworks.

2
MCP 层开发
MCP Layer

将 Pixel 数据库封装为 MCP 接口

Wrap Pixel database as MCP interface

覆盖核心查询场景：时间段内的事件流水、渠道归因数据、转化漏斗分析、all-ping 竞品维度切分。MCP 需支持异常处理和动态参数。

Cover core query scenarios: event logs by time range, channel attribution data, conversion funnel analysis, all-ping competitive breakdowns. Must support anomaly handling and dynamic parameters.

3
归因模型构建 — 核心阶段
Attribution Model — Core Phase

设计并验证第一版 CTV Web 端归因模型

Design and validate the first CTV web attribution model

最核心、最具挑战的阶段。CTV 归因难点：用户在电视上看广告，却在另一台设备上转化，两者之间没有确定性关联。需基于 Phase 1 的数据字段（IP、User Agent、时间戳、地理位置等），设计匹配逻辑和归因规则，定义 lookback window，用真实数据反复验证假设，大量依赖 Phase 2 的 MCP 进行高效查询和交叉验证。

The most critical and challenging phase. The CTV attribution challenge: users see ads on TV but convert on a different device, with no deterministic link. Requires designing matching logic and attribution rules based on Phase 1 data fields (IP, User Agent, timestamps, geolocation, etc.), defining lookback windows, and repeatedly validating hypotheses against real data — heavily relying on Phase 2's MCP for cross-validation.

4
AI 原生前端
AI-Native Frontend

打通"自然语言 → 数据 → 即时可视化"完整链路

Close the full loop: natural language → data → instant visualization

通过 Claude 调用 MCP，由 AI 根据自然语言需求动态生成数据视图。此时前端呈现的核心内容就是 Phase 3 建立的归因结果和竞品对比分析。

Claude calls MCP to dynamically generate data views from natural language queries. The core content is the attribution results and competitive analysis built in Phase 3.

5
主动洞察与行动引擎
Proactive Insights & Action Engine

从"人问 AI 答"升级为"AI 主动推送"

Upgrade from "human asks" to "AI proactively alerts"

建立持续监测机制，AI 自动识别异常、趋势和商业机会，以告警或简报形式推送给相关角色。核心场景：partner 转化率异常检测、广告主 upsell 机会识别、竞品渠道效果变动追踪，以及自动生成可执行行动素材（客户汇报、outreach 话术等）。

Establish continuous monitoring. AI auto-identifies anomalies, trends, and business opportunities, pushing alerts and briefings to relevant roles. Core scenarios: partner conversion anomaly detection, advertiser upsell signal identification, competitive channel tracking, and auto-generating actionable materials (client reports, outreach copy, etc.).

6
归因模型自进化与产品化
Model Self-Evolution & Productization

模型自迭代，并探索对外服务可能性

Self-iterating model, exploring external service potential

AI 持续用新数据验证和迭代归因模型——自动测试不同 lookback window、匹配规则的效果差异，推荐当前最优方案。同时探索将这套归因能力产品化，例如向广告主提供 CTV Web 端归因报告作为增值服务。

AI continuously validates and iterates the attribution model using new data — auto-testing different lookback windows and matching rules, recommending the current optimal approach. Simultaneously explore productizing this capability, e.g. offering CTV web attribution reports to advertisers as a value-added service.
